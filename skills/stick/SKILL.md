# Stick

Make the supplied material easy to recall.

The supplied material is the target. Do not turn the response into a general explanation, reference entry, or open-ended lesson. Build the shortest useful path back to that target, then stop.

## Core method

1. State the target's core meaning or function in one short sentence.
2. Preserve the target's own structure and expose only the distinctions needed to remember it.
3. Add one compact memory cue when it improves retrieval. Accuracy comes first: a cue may use sound, spelling, contrast, an image, or a causal link, but an invented association must be clearly labeled as a mnemonic and never presented as factual origin or meaning.
4. Add background only when it directly explains a confusing part or strengthens the memory cue. Do not add related facts, use cases, warnings, history, comparisons, or extensions merely because they are relevant.
5. Stop when the target can be recalled. Do not fill a template or add optional sections for completeness.

### Commands and syntax

Start with what the whole command does. Then read it left to right and preserve meaningful syntax units.

For each abbreviation, show:

| token | expansion | function |
|---|---|---|
| `<token>` | **<matching letters>**... | what this part does |

In `expansion`, bold only the letters that actually map to the full words. Map them in their actual order, including multiple letters drawn from one word; the mapping need not be one letter per word. Keep a flag with the value it governs when they form one filter or selector. Do not split a compound argument into artificial rows. Keep the bold markers outside code spans so they render. Do not repeat the letter mapping in `function`.

Use the table only when it makes the command easier to remember. Do not add grammar diagrams, alternative commands, or nearby variations unless the user asks for them.

### Words and terminology

Start with the word's meaning in the supplied context. When the target is a word or term, check its real formation before inventing a memory cue:

1. **Origin and formation**: identify a reliable etymology, compound, acronym, technical stem, or naming convention when one exists. Show the source parts and how they connect to the current meaning. For coined scientific or product names, explain the recognized naming elements rather than substituting related facts about the product.
2. **Word shape**: use a transparent prefix, suffix, root, cognate, or compound when it explains the meaning.
3. **Pronunciation**: use a stressed syllable, syllable split, or IPA when sound helps.
4. **Mnemonic**: use a short sound, image, contrast, or example hook whenever it helps recall, including an invented association when useful. Label it explicitly as a mnemonic, and keep it separate from the word's real origin and meaning.

If the origin is uncertain, verify it rather than guessing. If no reliable origin is available, say so briefly and move to the next useful cue. Never infer an etymology from visual resemblance or from a coincidental substring. Do not add definitions of related terms, product lists, history, safety information, or broad domain context unless those items are part of the material the user wants to remember.

### Concepts, lists, and procedures

For a concept, preserve its key distinction or causal chain in the smallest useful form. For a list, group items only when the grouping improves recall. For a procedure, preserve the actual order and attach a brief cue to the step most likely to be forgotten.

Use a mnemonic only after the structure is clear. Avoid generic study advice, tangential examples, and open-ended extensions.
